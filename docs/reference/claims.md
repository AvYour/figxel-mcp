# Claim Registry — figma-mcp

Every external fact that the **design depends on** is recorded here with an ID, source, and status. Other documents mark claims with `[C-0xx]`.

**Why this exists:** within a single design session, four mistakes were found — the quota figures (20 vs 6), the yield primitive (`setTimeout`), video export (the API changed in July 2026), and the parity map (the official server has no granular write tools). All four were the same type: **an external claim that was never tracked**. This registry makes claims re-checkable instead of permanently trusted.

## Status

| Status | Meaning | Action |
|---|---|---|
| `verified` | Checked directly against a primary source; the quotation is in the Source column | May be used as a load-bearer |
| `corrected` | **Was once wrong**, now fixed | Read the correction note before changing a document that uses it |
| `contradiction` | **Sources conflict with each other** | Do not assert as true; it must be tested (spike) |
| `measured` | Measured on this machine, not read from a document | Re-measure if the environment changes |
| `to-verify` | An assumption the design rests on | **Must be tested before being relied on** |
| `decision` | Our choice, not an external fact | Cannot be "wrong"; can be revisited |

## Rules

1. **Claims the design rests on must have an ID.** If a document states an external fact that shapes the design, it belongs here.
2. **Sources must be specific** — page URL + what it says + date accessed. "Figma docs" is not a source.
3. **`contradiction` may not be used as a load-bearer.** When two official sources disagree, that is a signal to test, not to pick whichever is convenient.
4. **A claim changes → the documents change.** After re-verification, find the claim's users (via its ID) and update them.
5. **Only the main agent updates this registry.** Verification subagents report only — this prevents two writers from colliding.
