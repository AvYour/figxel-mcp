# Tool Catalog — Figxel

The complete reference for every tool the Figxel MCP server exposes. **This document is the source of truth for the tool list and its counts** — the spec and README point here, and `scripts/check-docs.mjs` verifies that heading counts match table rows.

**Count: 144 tools in the catalog → 140 registered by default** (`figma_eval` is only registered when `BRIDGE_ALLOW_EVAL=1`, and the three tools of the held-back `audio` group only when `BRIDGE_ENABLE_AUDIO=1`).

| Group | Count | Nature |
|---|---|---|
| meta | 5 | Status, skills & viewport — does not modify the document |
| read | 24 | Reads the document |
| create | 34 | Writes the document |
| modify | 47 | Writes the document |
| style | 24 | Writes the document |
| export | 6 | Reads the document or a rendered file, writes files to disk |
| audio | 3 | Held back from the release, opt-in: sound files on disk |
| eval | 1 | Escape hatch, opt-in |

## Resources

Not tools, but part of the surface: `figxel://session/<sessionId>/selection` returns the last selection the
plugin reported, as JSON. It costs no Figma work (the plugin pushes the change and the bridge stores it), it can be addressed
by session id or file name, and it is listed per connected session so a client can discover it without calling a tool. It
refuses to answer for an unknown session rather than returning another session's data.

The skills are resources as well, read from the same tree in `src/skills` that `figma_get_guide` serves `[C-169]`: one static
`skill://figxel-<short>/SKILL.md` per skill (named and described by its frontmatter, the file's bytes as they are), and the
template `skill://{skill}/references/{section}.md`, whose list returns every section of every skill. Each is `text/markdown`
with its `size` and `audience: ["assistant"]`; the layout follows the skills extension `[C-172]`. They are registered
whatever `BRIDGE_TOOLSET` says.


## Conventions (apply to every tool)

- Every tool is prefixed `figma_`. The **op** name in the WebSocket protocol is the tool name without the prefix (`figma_create_frame` → op `create_frame`).
- `nodeId` accepts `"1:2"` (canonical), `"1-2"` (URL form), an instance id (`"I1-2;3-4"`, `%3B` decoded) or a figma.com link to the layer (`/design/`, `/file/`, `/proto/`, `/board/`, `/slides/`, with or without `/branch/<key>/`) — normalized automatically by the bridge for every id parameter (`nodeId`, `nodeIds`, `parentId`, `componentId`, `pageId`, a reaction's `destinationId`, `slideId`, `slideIds`, `afterSlideId`, `beforeSlideId`, …, also inside a parsed spec, inside a batch's steps and inside the `reactions` JSON string). A link names its editor (`/board/` FigJam, `/slides/` Figma Slides, the rest Figma Design): among same-named connected files the one in that editor is picked, and a write whose link points at another editor's file is refused with `INVALID_PARAM` (a read runs with a `warning`). Other id grammars (`S:…`, `VariableID:…`, keys) pass unchanged. A link with no `node-id`, a link to another site, or links into two different files are refused with `INVALID_PARAM` before Figma is asked. With no `session`, a link's file name picks the session when several files are open; with one session whose file name differs, a read runs and carries a `warning` (an error result carries it too), while a write is refused with `INVALID_PARAM` before Figma is asked — node ids are per file, so the same id in the open file is usually an unrelated layer; pass `session` with the open file's name to run it anyway (a renamed file). Tools taking many nodes use `nodeIds: string[]`.
- All parameters are validated by zod **before** touching Figma. An unknown key is refused with its path, never stripped — at the top level of every tool and inside every nested object. Validation errors (`INVALID_PARAM`) carry the offending field path.
- **`session?`** (every tool that reaches Figma: all but `figma_status`, `figma_get_guide`, `figma_review_video`, `figma_analyze_audio` and `figma_add_audio`): a `sessionId` or file name, to pick a plugin when more than one Figma file is connected. Without it, the most recently active session is used.
- **Editors:** a tool runs only in the editors § [Editor support](#editor-support) allows `[C-129]`. Elsewhere the bridge refuses it before Figma is asked — `UNSUPPORTED` naming the editor and the file, `partial: { created: [] }`, `safeToRetry: true`, and a hint naming a connected file where it runs. A file name shared by several files picks the one whose editor runs the tool. A description ends with an `Editors:` sentence when the tool does not run everywhere (`Editors: FigJam only, unverified.`), and `figma_status` lists each file's `unavailableTools`.
- **`idempotencyKey?`** (every tool in the `create`, `modify`, `style`, `eval` groups): a string ≤128 characters. When supplied, re-calling with the same key **never executes twice** — it returns the existing result, or waits for the op still in flight. When empty, the bridge generates a key and returns it in results/errors. **For large ops, supply your own** (e.g. `"landing-hero-v1"`): if the MCP client times out (not the bridge), only an agent-owned key can be used to retry safely. Detail: [protocol.md §3](protocol.md#3-messages-server--plugin).
- **Parameters that would need a union travel as one string**, so every schema stays inside the conservative subset `test/schema-portability.test.ts` enforces: padding `"24"` or `"48,48,32,32"`, weight `"600"` or `"Semi Bold"`, a variable value `"16"` / `"#1a2b3c"` / `"true"`, a z-order index `"3"`, a zoom `"1.5"`. Recursive or heterogeneous shapes (`spec`, `reactions`, `properties`, a batch's `steps`) travel as a JSON string. The plugin parses each form and rejects anything else with `INVALID_PARAM` naming the field — nothing is accepted and then dropped.
- **`sizing`** (create and resize tools) is Figma's own Horizontal / Vertical sizing dropdown per axis: `{ "horizontal": "fixed" | "hug" | "fill", "vertical": … }`. `hug` works on auto-layout frames and text, `fill` on children of an auto-layout — anything else is refused with the rule that was broken.
- **Checks run before the document changes.** A write op validates every parameter it can before touching a node; a failure that provably changed nothing carries `partial: { created: [] }` and does not pin its `idempotencyKey` ([protocol.md §3](protocol.md#3-messages-server--plugin)).
- **Every error carries `safeToRetry`** (in `structuredContent`) `[C-096]`: `true` only on evidence that the document is unchanged — the tool only reads, the call was refused before it reached Figma, the plugin reported `partial: { created: [] }`, or the code is `NO_SESSION` / `BUSY` / `PORT_IN_USE` for a call that never reached the plugin. A `NO_SESSION` carrying `partial: { dispatched: true }` (the connection was lost after the plugin had the call) is `false` `[C-096]`. `false` (a timeout, a failure half-way through a write, a connection lost mid-call) means read the canvas (`figma_get_node`) before calling again.
- **A page or node Figma could not load for the plugin.** Under dynamic-page another page is loaded on demand `[C-090]`. When Figma gives up, its own text ("Unable to establish connection to Figma after 10 seconds. …") is quoted inside an error that names what was asked for `[C-262]`: `TIMEOUT` when the text says Figma gave up after a time, `INTERNAL` otherwise. The hint suggests `figma_navigate_page { pageId }` or a retry. A read stays `safeToRetry: true`.
- **Multi-node ops return per-item results** (`[{id, ok, error?}]`), not all-or-nothing. When an item is `"not found"` in `figma_move_nodes`, `figma_resize_nodes`, `figma_rotate_nodes`, `figma_reorder_nodes`, `figma_reparent_nodes`, `figma_delete_nodes`, `figma_group_nodes`, `figma_ungroup_nodes`, `figma_set_visible`, `figma_set_locked`, `figma_set_opacity`, `figma_set_clips_content` or `figma_set_constraints`, the result adds one `hint`, and a `NODE_NOT_FOUND` from the modify and motion tools carries the same one: an id read from a listing inside an animated frame can be temporary, so use the id the create call returned `[C-199]`.
- **The motion process is enforced by the tools** (`BRIDGE_PROCESS`, default `strict`) `[C-338]`: `figma_set_keyframes` and `figma_remove_keyframes` (directly or as `figma_batch` steps) need this process to have read the motion or storyboard skill (`figma_get_guide`, the `animate_in_figma` or `storyboard_motion` prompt, or their `skill://` resources) and the layer's top-level frame to carry a plan (`figma_set_motion_plan`); `figma_export_video` with `final: true` needs the last `figma_check_motion` on that frame in this process to have passed whole (no `rules`, `from` or `to`, nothing truncated) at the render's fps as the plan's own check, against the plan the frame still carries, with no change to the file since. The check applies the plan's `bpm`, `beatOffset`, `holds`, `brandId`, `ctaId` and `accept`; a call looser than them or than the defaults (another tempo, brand or CTA, a hold outside the plan's, a threshold off its default, a later `brandBy`, a shorter `ctaMinS`) runs as asked but does not count. A change is any write sent through this process or any change the plugin reports on its current page (`lastNodesChanged`, from `nodechange`): an undo, a clone, a text edit, `figma_eval`, another client and an edit by hand alike. A change reported from the moment the check began counts, so an edit made just before it can too, at the cost of one more check. A finding the brief intends is accepted in the plan (`accept`, with its reason), never by loosening the check, and the delivery's result lists it. `strict` refuses before anything is sent with `PROCESS_REQUIRED` (`partial: { created: [], missing }`, `safeToRetry: true`), naming the calls that satisfy it; `guided` runs the call and adds `processWarnings`; `off` tracks nothing. The plan lives in the file, so every process sees it; the rest is the state of the process serving the client (a proxy keeps its own), kept per frame of each connected file. A preview render is never gated.
- **The role process is enforced by the tools** too, under the same `BRIDGE_PROCESS` (spec ADR #42): **new work** waits for a brief in force for its file — `figma_create_frame` or `figma_create_section` at page level, `figma_create_from_spec` whose frame, component or section root lands on the page or whose parent is an empty top-level frame or section, `figma_create_slides` or a spec into a deck with no content, and every `figma_create_storyboard` (directly or as `figma_batch` steps). Edits never wait: clones, pages, single texts, shapes and images, instances, and every modify and style tool. A brief is in force once this process stored it (`figma_set_brief`) or read it open (`figma_get_brief`), until a passing `figma_sign_off`; with one in force the gate reads nothing, without one it reads the file's briefs once and, when the file holds an open brief, names it to adopt. `figma_set_brief` waits for the role's skill read in this process (`figma_get_guide`, a prompt or a `skill://` resource; at the page gears the design skill too). `figma_export_node` and `figma_export_frames_to_pdf` with `final: true` need, on every node that belongs to a brief, a passing sign-off whose fingerprint equals the node's now; a node of no brief exports, and without `final` nothing is gated. `strict` refuses before anything is sent with `PROCESS_REQUIRED`, as the motion process does; `guided` runs and adds `processWarnings`; `off` tracks nothing, and the three tools still work. `strict` runs as `guided`, and `figma_status` says why in `process.roles`, where it could not be satisfied: a toolset without `figma_set_brief` or `figma_get_guide` (for a final export, without `figma_sign_off`), or a file whose editor does not run `figma_set_brief` (or `figma_sign_off`) yet. A plugin that predates briefs is refused in `strict` with the hint to run it again.
- **Every write is guarded against overwriting someone else's edit** (`BRIDGE_CONFLICTS`, default `refuse`; spec ADR #43) `[C-397]`: a write to a node a person or collaborator changed after the agent last read or wrote it answers `STALE` before any change; `force: true` (every write tool takes it) overwrites on purpose, and `warn` lists the conflict under `conflicts` instead. Every write is journalled for `figma_get_changes`; `figma_savepoint` and `figma_rollback` take back a whole instruction, and a rollback refuses (`ROLLBACK_BLOCKED`) whenever it would also undo someone else's edit or another agent's call.
- **Every write op ends with a single `figma.commitUndo()`** → one tool call = one Ctrl+Z step for the user.
- **MCP annotations:** the `meta`/`read`/`export` groups use `readOnlyHint: true`; `figma_delete_nodes`, `figma_detach_instance`, `figma_ungroup_nodes`, `figma_delete_variable`, `figma_delete_variable_collection`, `figma_delete_style`, `figma_delete_component_property`, `figma_update_variable_collection` (removing a mode loses its values), `figma_reset_slot`, `figma_edit_table` (removed rows and columns lose their cells), `figma_undo_step`, `figma_rollback` (it undoes every call since a savepoint), and `figma_eval` use `destructiveHint: true`; none of them runs inside a batch. Clients with an approval mode can make use of this.

### Trimming the toolset

Every tool is registered by default. To trim (save tokens / reduce mis-selection) there are two routes:

| Route | How | When to use |
|---|---|---|
| **Client tool picker** (recommended) | The MCP client's own picker, where it has one (e.g. `hermes mcp configure figxel`) — tick/untick tools per server, without changing bridge code | Daily use in a client that has a picker |
| **Server env var** | `BRIDGE_TOOLSET=…` (table below) | Clients with no tool picker, Docker/headless, debugging |

| `BRIDGE_TOOLSET` | Contents |
|---|---|
| *(unset)* / `full` | Every group — **default** |
| `core` | A curated 20-tool subset (listed below) |
| A group list, e.g. `read,export` | Only the named groups, plus `figma_status` and `figma_get_guide`; group names are `meta`, `read`, `create`, `modify`, `style`, `export`, `audio`, `eval` |
| `none` | Only `figma_status` (connection debugging) |

Standing rules:
- **`figma_status` is always registered**, whatever `BRIDGE_TOOLSET` says — without it the connection cannot be diagnosed.
- **`figma_get_guide` is registered in every toolset except `none`** — the skills it serves are how an agent learns to use whichever tools it was given.
- **`figma_eval` needs two keys:** `BRIDGE_ALLOW_EVAL=1` **and** a toolset that includes the `eval` group (`full` does; `core` does not).
- **The `audio` group needs two keys too:** `BRIDGE_ENABLE_AUDIO=1` **and** a toolset that includes the `audio` group (`full` does; `core` does not). The group is held back from the release (§ [audio](#audio-3)); the flag is for development only.
- An unrecognised value → the server refuses to start with a message on stderr (rather than silently falling back to `full`).

The `core` tier (20) = `figma_status`, `figma_get_guide`, `figma_check_layout`, `figma_get_design_context`, `figma_get_node`, `figma_get_selection`, `figma_export_node`, `figma_create_from_spec`, `figma_create_frame`, `figma_create_text`, `figma_set_text`, `figma_set_fills`, `figma_move_nodes`, `figma_resize_nodes`, `figma_delete_nodes`, `figma_search_nodes`, `figma_get_variable_defs`, `figma_get_styles`, `figma_navigate_page`, `figma_zoom_to`.

> **On tool-selection accuracy:** if the agent often picks wrongly between `figma_set_fills` / `figma_set_strokes` / `figma_apply_style_to_node`, the fix is **sharper tool descriptions**, not hiding tools. Each description states its discriminator explicitly (e.g. "`set_fills` changes the fill colour; to apply a named style use `apply_style_to_node`").

### The "Official" column

This compares against the **official Figma MCP** (`mcp.figma.com`) `[C-008]`. The official tool list was retaken on **2026-10-08** from the official plugin bundle 2.2.120 and the official tools page `[C-087]` — recheck it when writing user documentation, since it changes.

| Marker | Meaning |
|---|---|
| `✅ x` | Official tool `x` does the same thing |
| `🔁 x` | Official tool `x` covers the same need in a different shape |
| `JS` | On the official server this is only reachable through `use_figma` (running raw Plugin API JavaScript); here it is a typed tool with a schema and validation |

The official server has **no** granular write tools (`create_frame`, `set_fills`, …) — every canvas write there goes through `use_figma`. The granular names in this catalog follow community-project convention (`cursor-talk-to-figma-mcp`, `figma-mcp-rust`) so they are familiar to agents.

## read (24)

Every read returns a normalized DTO (not raw Figma JSON) and respects `depth` + `maxNodes`. When truncated, the result carries `truncated: true` + `nextCursor`; call again with `cursor` to continue — **large documents are split, never rejected**.

Reads run in every editor. Outside Figma Design every node member is read through a guard, because a member a node type lacks may throw there rather than read as undefined `[C-145]`; a Slides deck's `SLIDE_GRID`, `SLIDE_ROW` and interactive elements are opaque and only their id, name, type and box are reported `[C-136]`. FigJam and Slides nodes add a short preview to every DTO (`figma_get_node`, `figma_get_nodes_info`, `figma_get_selection`, `figma_search_nodes`, `figma_scan_nodes_by_types`): a sticky's or shape's text (cut at 200 characters, with `textLength`), `shapeType`, a code block's `language`, a connector's `{ from, to, label }`, a table's size, a link, a section's `sectionContentsHidden`, a slide's `{ row, col, index, skipped }`. Design DTOs are unchanged.

```jsonc
  "ref": "hero",               // a name for this node within the call; a connector names it as an end; returned in `refs`
  "width": 1200, "height": 600,
  "layout": "vertical",        // horizontal | vertical | none
  "sizing": "fixed",           // fixed | hug — defaults to fixed when width/height are given (current-state §3 lesson)
  "gap": 24,
  "padding": [48, 48, 48, 48], // or a number
  "alignX": "center", "alignY": "center",  // start | center | end | space-between — screen directions; alignY "baseline" in a row
  "wrap": true, "rowGap": 16, "alignContent": "auto",  // a wrapping row: rowGap (default: gap) between rows; auto | space-between
  "positioning": "absolute",   // a child out of its auto-layout parent's flow, placed by x/y (a badge); "auto" = in the flow
  "background": "#ffffff",     // omitted: a nested frame is transparent, a frame on the page is white
  "variableModes": { "Theme": "Dark" },  // frame / button / component / section: pin a collection's mode (name or id)
  "variables": { "fill": "color/bg/default", "gap": "space/4" },  // bind variables by name or id
  "style": { "text": "typography/heading-xl" },  // apply local styles by name or id: fill | stroke | text | effect | grid
  "componentId": "12:3",       // type "instance": a COMPONENT or COMPONENT_SET id — or componentKey / componentSetKey; no children
  "variant": "Size=Large, State=Hover",  // instance of a set: which variant
  "properties": { "Label": "Buy now", "Show icon": false },  // instance: set in the same call
  "nested": { "Icon": { "Name": "arrow-right" } },  // instance: properties of nested instances, by layer name
  "children": [ /* recursive */ ]

```

Rules:
- Everything a build could trip over half-way — layout, alignment, padding, colours, the shape of `variables` / `style`, every name, id, key, mode and property the spec refers to, a component nested in a component — is checked **before the first node exists**; such a failure reports `partial.created: []`.
- **A field a node type does not take is refused**, with the nearest valid name and `partial: { created: [], failedAt: "<path>" }` — never silently ignored. A `text` takes no `height`.
- `alignX` / `alignY` are screen directions, mapped onto Figma's axes by the layout direction (in a row x is the primary axis, in a column y is). `space-between` exists only along the layout direction; `baseline` only as `alignY` of a row.
- `wrap` needs a horizontal layout; `rowGap` and `alignContent` apply only to a wrapping container `[C-095]`.
- `positioning: "absolute"` needs an auto-layout parent and cannot be combined with `sizing` fill `[C-095]`; under a frame without auto-layout `x` / `y` already place a child.
- `variableModes` maps a collection (name or id) to a mode (name or id) on a frame, button, component or section; it is applied after a component is converted `[C-105]`.
- `variables` binds variables to fields: `fill` / `stroke` (COLOR variables), `radius`, `gap`, `padding` (all four sides), `size` (width and height), or any Figma bindable field name. A name or a `VariableID:` id; not found → `INVALID_PARAM` plus the nearest names. An `svg` binds its colour with `colorVariable`, not `variables.fill`.
- `style` applies a local style **by name** or by `S:` id. Not found → `INVALID_PARAM` plus the 5 nearest suggestions (fuzzy).
- A variable whose type the field cannot take (a FLOAT on `fill`, a COLOR on `gap`), a field no variable binds, and a style whose kind does not fit its slot (a PAINT style as `text`, by id) are refused before the first node.
- `x` / `y` on a node an auto-layout places (a child, or a root whose parent has auto-layout) are refused unless it has `positioning: "absolute"`; `gap` / `padding` need `layout` horizontal or vertical. `sizing` is `fixed` / `hug` / `fill` or `{ "width": …, "height": … }` with those words: `hug` only on a text or an auto-layout frame / button / component, `fill` only under an auto-layout parent.
- Numbers are checked before the first node: `width` / `height` ≥ 0.01 (Figma's resize minimum), `fontSize` ≥ 1, `strokeWeight` / `cornerRadius` ≥ 0. A text's `align` is left, center, right or justified; its `lineHeight` (`"auto"`, `"24"`, `"24px"`, `"150%"`; ≥ 0) and `letterSpacing` (`"0.5"`, `"-2%"`) take the strings of `figma_set_text_properties` and what `figma_get_design_context` reads back, and a bare number as px.
- An `instance` takes exactly one of `componentId`, `componentKey`, `componentSetKey` (a key is imported first `[C-110]`), `variant` for a set, `properties` (`{ name or key: string | boolean }`), `nested` (`{ layer name: properties }`), and `width` / `height`, which resize it. A slot is filled afterwards with `parentId` = the slot `[C-112]`.
- Shapes and assets: `polygon` / `star` take `pointCount` (and `innerRadius` for a star); `line` takes `width` as its length, `stroke`/`color`, `strokeWeight`, `cap`; `vector` takes `path` (SVG path data); `svg` takes `svg` markup, scaled by `width`/`height` and recoloured by `color` or bound by `colorVariable` (a COLOR variable name or id); `image` takes `url` and `scaleMode`. Only `frame`, `button`, `component` and `section` take children `[C-083]`.
- Every `image` URL is fetched **before the first node exists**, so an unreachable image fails the call with `partial.created: []` instead of half-way through.
- A `component` is built as a frame and converted after its children exist (`figma.createComponentFromNode` `[C-056]`); its entry in `created[]` carries the component's id. An `instance` comes from `ComponentNode.createInstance()`.
- Fonts: ordered fallback Inter → Roboto → Arial → Helvetica Neue (the old logic). All fail → `FONT_LOAD_FAILED` plus the list of available fonts. A text entry in `created[]` carries `font: { family, style, fellBack: true }` whenever the font used is not the one asked for. Note: Inter style names use spaces (`"Semi Bold"`, not `"SemiBold"`).
- The whole spec is **one** `commitUndo()` → one Ctrl+Z undoes the entire screen.
- Mid-way failure → `{ ok: false, partial: true, created: [{id, name, path}], failedAt: "<path in spec>", error }`. No automatic rollback; the user can Ctrl+Z, and the agent can continue from `failedAt`.
- Large specs are built in ~12 ms slices with a yield to Figma between them and `progress` (done / total nodes) — the node count is not capped, and a cancel stops at the next slice with everything built so far reported.
- **Several roots:** `spec` may be a JSON array of 1–50 roots when `parentId` or `pageId` says where they go — the content of one slide, the cards of one zone. One validation, one undo step; the result adds `rootIds`.
- **`ref`** names a node within the call (letters, digits, `_`, `-`; unique across the call, refused before the first node otherwise). The result's `refs` maps each to its id.
- **`list`** on a text: `unordered` / `ordered` / `none` — every line becomes a bullet or a number, one text node rather than a dot beside each line `[C-155]`.
- **Sections** have no auto-layout: `arrange` (`row` / `column` / `grid:N`) places the children from their real sizes, rows as tall as their tallest item; `gap` (default 64) spaces them and `padding` (default 32) insets them — both only with `arrange` or `hug` `[C-166]`; `hug: true` fits the section to its children plus padding, inner sections first, through `resizeWithoutConstraints` `[C-141]` (conflicting sources; a live spike settles it) (not with a size); `contentsHidden`; `name: ""`. A child of an arranged section takes no `x` / `y`.
- **FigJam types** (registered spec types; none takes children): `sticky` { `content`, `color`, `wide`, `authorVisible`, `x`, `y` } — no size; `shape` { `shape`, `content`, `color` \| `fill` / `stroke` / `textColor`, `width` + `height`, `fontSize`, `x`, `y` }; `table` { `rows` \| `numRows` + `numColumns`, `header`, `headerColor`, `fill`, `columnWidths`, `rowHeights`, `fontFamily`, `weight`, `fontSize`, `x`, `y` }; `code` { `content`, `language`, `x`, `y` }; `connector` { `from`, `to` (a ref, `"<ref>@<magnet>"`, a node id or `"x,y"`), `label`, `lineType`, `startCap`, `endCap`, `color`, `strokeWeight`, `dash`, `labelBackground` }. A connector is **deferred**: built after every other node of the call, in the container that declares it, never moved afterwards `[C-149]`; it takes no `x`, `y`, `width` or `height`. They build through the same code as the FigJam tools.
- **Per editor:** a node whose type or field the file's editor cannot run is refused before the first node, `UNSUPPORTED` with `failedAt` — a component on a board (the cell of `figma_convert_to_component`), a FigJam type outside FigJam, or a type whose factory the editor lacks (feature-detected, never assumed `[C-145]`). On a board, text defaults to Inter Medium in Charcoal #1E1E1E `[C-156]`.
- **On a slide** the build is top-down: each node is appended to its real parent before any size or `x` / `y` is written, because a position set first can land 240 px off `[C-146]`; every placed position is read back into `drift` (expected `[]`, never compensated). A root that would `fill` its slide is refused — a slide is not an auto-layout parent. Design files keep the bottom-up order exactly as before.

### Official tools with no counterpart

| Official tool | Reason |
|---|---|
| `add_code_connect_map`, `get_code_connect_map`, `get_code_connect_suggestions`, `get_context_for_code_connect`, `list_file_components_for_code_connect`, `send_code_connect_mappings` | Code Connect data lives in Figma's service; the plugin API has no access to it. |
| `create_new_file` | File creation is account-level. Workaround: the user creates a file, then opens the plugin there. |
| `generate_figma_design` | Live URL capture by Figma's server. |
| `generate_image`, `weave_*`, `get_figma_skill`, `create_shader`, `update_shader`, `*_generative_plugin*` | Figma hosted services (AI, shader and generative-plugin authoring), not document content. Applying a shader that already exists in the file is plugin-reachable — see Candidates. |
| `search_design_system` (components and styles), `get_libraries` | Library search for components and styles is unavailable to plugins: a plugin imports a library asset only when it already knows the key (`figma_import_library_assets` `[C-110]`), and `figma.teamLibrary` lists **variables** only — which `figma_get_library_variables` covers `[C-107]`. Keys of library assets the file already uses are read from `figma_get_design_context` and `figma_get_component`. |
| `generate_diagram` | Hosted: Mermaid or a description laid out by Figma's service `[C-154]`. Hand-built diagrams use `figma_create_shapes_with_text`, `figma_create_connectors` and `figma_create_from_spec` (shapes and connectors joined by `ref`, one zone per call); a local layout tool is a candidate (`figma_create_diagram`). Its FigJam reader, `get_figjam`, is covered by `figma_get_design_context` (board node types and the `connectors` edge list) plus `figma_export_node` `[C-153]`. |
| `generate_deck` | Hosted deck templates `[C-087]`. Decks are built with `figma_create_slides` and one `figma_create_from_spec` per slide. |

## Claims we can make

**We can:** everything the official `use_figma` can do is doable here (typed tools, or `figma_eval`), plus reading design context / screenshots / variables — free, local, no quota.

**We cannot:** 100% tool-per-tool parity. Code Connect, hosted AI services, hosted generation (`generate_diagram`'s layout, `generate_deck` templates), component and style library search, Slides templates and themes, and creating interactive slide elements are out of the plugin's reach; Dev Mode stays out by decision `[C-128]`. FigJam and Slides themselves are in reach — tool by tool as § [Editor support](#editor-support) records.
