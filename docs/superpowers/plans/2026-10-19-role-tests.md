# Role tests on a real canvas — 2026-10-19

The agent (Claude, through this repository's own MCP server) worked each role end to end in Figma desktop, the way a client agent would: the role's skill, the brief, the build, the role's audits, the stress test, the sign-off and the final export. The owner watched and made the person's edits. Server and plugin on build `83ea2daed558` (0.1.1 + the role process and trust, unreleased), Windows, Figma desktop, `BRIDGE_PROCESS=strict`, `BRIDGE_CONFLICTS=refuse`.

Everything was built on the page "Figxel — Role tests" of the owner's scratch file.

## UX, page gear — "Tool reservation"

One iOS screen (`Reserve / 01 Drill`, 390 × 844) with its Empty, Loading and Error frames, a `Button` set (Default, Pressed, Focus, Disabled, Loading) and a `Weekend` set (Default, Selected, Pressed, Focus, Disabled), a "Tool library" variable collection for the brief's palette. Signed off on the second call; the final export ran, and was refused after an edit.

### What worked

- The brief: `lint` empty, `missingForSignOff` named exactly what sign-off later asked for (directions, the choice, a styleframe, the system).
- `STALE` on a real edit: the owner changed the Kit text in Figma; the agent's next `figma_set_text` on it was refused, and the edit survived. That event arrived on time while the owner worked in Figma.
- The stress test found two real breaks on the first run: the shelf code overflowing its row under `expand`, and the weekend list running under the action bar because the content region did not scroll.
- Sign-off listed every blocker with the call that clears it; one answer per node covered both of its infos.
- The final export gate: allowed right after the sign-off, refused after a one-word edit (fingerprint 68a0dbff → 5b6685d9), fresh again once the word was reverted.
- `weight: 600` resolved to "IBM Plex Sans SemiBold" (the family spells it without a space).

## An internal product: design system, UX

The owner switched the subject to an internal product of the owner's, whose `web/` already has a design system in code (MD3 dark from #FF6900, Heroicons, `docs/DESIGN.md`). The design-system role replicated it (64 variables from `tokens-report.json` with Tailwind code syntax, 15 MD3 text styles, 18 Heroicons extracted from the repo's `@heroicons/react` 2.2.0, a 26-variant Button set); the UX role built the Run view, its Empty and Error states and the Approval dialog, and signed off the three screens.

| 16 | Medium | spec `variables` | "2 variables are named radius/sm": the file holds another brand's collection with the same names, and the spec has no way to name the collection. The owner then asked for a calmer palette: the seed-generated Fidelity scheme read as brown and peach. The variables gained a Light mode and new values for both modes (neutral greys, the orange kept as the accent), 154 contrast pairs checked at AA before they were applied; the screens followed through their bindings, and Light copies pin the new mode.

Other observations: the Button's state layers needed alpha in the variable's value (finding 15); a Button stretched to fill left its label at the start until each variant centred its content, a component mistake the audits did not name.

The earlier `live-trust` spike run (same day) fits finding 6: the owner's first edit was seen only minutes late, and the stress test found nothing because its fixed-width cards held texts that filled and wrapped.
