# figma-mcp: design, motion and storyboard skills, and the four defects — implementation plan

Date 2026-10-13. Branch `feat/figjam-slides` (129 tools) when written. Status: waves 1 and 2 built and unit-tested, 133 tools; most live runs still to do — see [Results of wave 1 and 2](#results-of-wave-1-and-2). Written for the main agent, which integrates the work, edits the registries and the locked documents, and registers the claims.

The user asked for design and storyboard skills inside this MCP. This plan delivers four process skills (design, storyboard, motion, critique), the tools they need, and the fixes for the four defects of 2026-10-09.

Inputs: `research-design.md` (design-process), `research-motion.md` (motion-process), `delivery.md`, `tools.md` (scratchpad), `bug-move.md`, and the bug-keyframes report (held in the workflow journal, because the harness refused its `.md` file; its probe is `kfwork/live-keyframe-tracks.mjs`). Ground truth: the 2026-10-09 run (`scratchpad/motion/`, `wf_c23489f2-d18/journal.jsonl`). Every report proposed its own claim numbers, and those numbers collided. Section 7 merges them into one list, C-168 to C-250, and those are the IDs used throughout.

## 0. Decisions in brief

1. **One source, five surfaces.** All agent guidance moves into Markdown skill folders under `src/skills/figma-mcp-<short>/` (an `SKILL.md` index plus `references/<section>.md`) [C-174] [C-237]. They are bundled into `dist/server.js` and served through:
   - `figma_get_guide`, which every client has;
   - a pointer in the server `instructions`;
   - MCP prompts;
   - `skill://` resources;
   - the folders themselves, installable as skills.

   `src/server/guides.ts` keeps only `SERVER_INSTRUCTIONS` and a derived `GUIDES` view.
2. **Eleven skills.** Four are new: `design`, `storyboard`, `critique`, and `motion`, which grows from today's topic. The other seven hold today's 16 topics unchanged. Every old topic name still resolves.
3. **The run is the model, compressed for one agent.** Directors, judges, builders and critics become passes that one agent runs one after another. Subagents are an optional speed-up, mentioned once in each skill [C-238].
4. **Four new tools (129 → 133):**
   - `figma_create_storyboard`;
   - `figma_create_animatic`;
   - `figma_check_motion`, which checks keyframes with no render;
   - `figma_review_video`, which mines one render without re-rendering.

   **Extended tools:** `figma_export_video` (job mode, frame-exact stills), `figma_check_layout` (`craft` and `tells` audits), `figma_import_image` (`renderNodeId`), `figma_get_guide`, `figma_get_motion_context`, `figma_set_keyframes`, `figma_remove_keyframes`, `figma_move_nodes`, `figma_batch` and `figma_status`.
5. **The four defects have one root:** Figma's "second id" periods inside an animated frame [C-199]. Our code made each one worse, by writing x and y as two setters, by echoing tracks without reading them back, and by reporting a timeline id as a node id. The fixes are defensive and correct whatever Figma's mechanism turns out to be [C-250]. Two live probes settle the mechanism. Build skew is ruled out: the code paths involved did not change between the run and today (`bug-move.md` H6; bug-keyframes §0).
6. **The render that died at the 60 s client timeout is our defect too.** The bridge forwarded the client's cancel, and that discarded a render Figma cannot stop [C-197]. Job mode fixes it for every client [C-249].
7. **Cut:**
   - a frame-grab tool, a beat-check tool, a storyboard-reader tool and an auto-fix tool;
   - `structuredContent` on `figma_get_guide`, because a client that prefers it would drop the guide text;
   - full skill names as topics;
   - a plugin-side render heartbeat;
   - the `regions` parameter on `figma_review_video`;
   - trimming on export;
   - the skills doctor;
   - a Claude Code plugin package.

   Section 6 gives the reasons.

### 1.2 Outline of each new skill

All skill text is written in our own words; no sentence is taken from any source or from the official skills, and T9 (§1.6) checks this mechanically. Every external fact cites its claim, and only `verified`, `measured` or `decision` claims may be cited [C-237].

#### `design` — index (SKILL.md)

- **Description:** "Design a page, screen, poster, slide or styleframe in Figma like a senior designer: write the brief, explore 2–3 directions, build styleframes, set a system, build, then critique with measured lenses until it signs off. Use before any new design larger than a few nodes."
- **Gear, stated first:**

  | Gear | Process |
  |---|---|
  | edit | match what is there; no process |
  | section | 3-line brief, 2 directions in words, 1 critique round with 3 lenses |
  | page or screen | full brief, 2–3 directions, a styleframe of the hero when unsure, 2 rounds |
  | campaign, poster, landing page, brand piece or styleframes for a storyboard | the whole process, 3 styleframes, up to 3 rounds |

  A brand, a system or a reference the user gave is a decision already made; the directions vary only what it leaves open [C-239].
- **The stages, one line each with their exit gate:** gear → brief → look → directions → styleframes and choice → system → build → critique → finish (§2.1).
- **Hard rules:**
  1. Write the brief before the first node.
  2. Never ship the first idea when the gear is page or larger.
  3. Every number comes from a stated rule.
  4. Measure, then look: `figma_check_layout { audit: ["craft", "tells"] }` before the render, and the render for what numbers cannot see [C-070].
  5. A tell that stays in the design is a decision written in the report.
  6. Fix with targeted edits, never by rebuilding.
  7. Stop at the sign-off bar or after three rounds.
- **Section list,** with the exact call for each one.

#### `design` — sections

**`brief`** (cites C-085, C-236):
- The brief is a decision record of seven lines:
  - goal;
  - audience, and where they meet the work;
  - the single message, in one sentence with no "and";
  - proof (2–3 facts);
  - constraints: format, safe zones read from the placement's current spec, brand givens, mandatory content, fonts that load (`figma_get_fonts`);
  - success, with the measurable checks it implies;
  - tone, as three words and one "not".
- Look before you design:
  - the subject's own world: materials, tools, words, places;
  - the category default: what three peers all do; keep the conventions people rely on and break the habits;
  - references by name, each with what is taken and what is left.
- Never copy a reference's layout or assets.
- Ask the user only when the message or the audience cannot be inferred and would change everything.
- Where the brief lives depends on the gear:
  - section: in the reply;
  - page or larger: a text block on an "Explorations" page.

**`directions`** (cites C-216, C-218, C-219, C-208):
- Two or three directions that differ in at least two of: idea, type, composition, colour, imagery. A colour swap is not a direction.
- A card per direction:
  - name;
  - the idea in one sentence;
  - why it fits;
  - the type pairing with roles;
  - a palette of 4–6 hex values with roles;
  - the composition rule;
  - one signature element;
  - its risk.
- **The default check:** would a similar brief for another client land here? Compare the card with the `tells` section. A match is either "brand given" or revised, never silent [C-208].
- **Styleframes:** one key frame per direction, built for real at delivery size, side by side on the Explorations page, named `Direction A · <name>`.
- Score each styleframe with the critique lenses (message, originality, type and composition at least).
- Choose a spine and graft the best of the others [C-216]. Write one decision line: chosen, why, grafted, rejected.

**`system`** (cites C-210, C-211, C-212, C-213, C-214, C-215, C-221, C-075, C-073, C-218):
- **Type:**
  - one family with real range, or two distinct ones;
  - sizes from a ratio anchored on the body;
  - few levels, with steps you can see;
  - measure 45–90 characters;
  - body leading 1.2–1.45;
  - lining figures for numbers people read;
  - caps only for short labels, tracked 5–12 %.
- **Grid:** columns, gutters and margins as numbers, and one deliberate break.
- **Composition:**
  - one focal point per view;
  - uneven splits;
  - tight inside groups, generous between them;
  - use the edges;
  - vary the skeleton between views [C-073].
- **Colour:**
  - roles: lead, support, accent with a stated rule, neutrals, text;
  - derived from the subject;
  - body text untinted;
  - contrast 4.5:1 for text, 3:1 for large text and for graphics people need [C-075] [C-221];
  - never colour as the only cue.
- **Radius, stroke and elevation:** set by role and size; a nested radius is the outer radius minus the inset; elevation only where something sits above something else.
- **Imagery:** relevant to the subject and art-directed (focal point, crop, temperature, what it proves) [C-213]; icons labelled [C-214].
- **Copy:** specific and objective, with real names and numbers [C-215].
- **What to save:** styles and variables, when the file should keep them.

**`tells`** (cites C-217, C-218, C-219, C-220, C-207, C-209, C-248): the generated-look catalogue, grouped by type, layout, surface, icons and images, copy, and motion. Each row says:
- why it reads as generated;
- the `check_layout` kind that measures it, or "by eye";
- the professional alternative.

The section also lists the finish defects from the run: build ≠ spec, near-misses, tangencies, edges slicing text, near-equal sizes, old-style figures, optical imbalance, associations, size for the device, weak graphic contrast, and inconsistent repeats. It closes with: any tell may be right for a brief, and then it is a choice the report states.

**`finish`** (cites C-207):
- **Details pass:**
  - optical alignment;
  - rag: break lines by sense, no one-word last line;
  - figures and punctuation consistent;
  - no tangencies;
  - read every mark cold for associations.
- **The report:**
  - the brief as built;
  - the direction and why;
  - the grafts;
  - placeholders to replace;
  - tells kept on purpose;
  - where the explorations are.
- **Then:** `figma_select` and `figma_zoom_to`.

#### `storyboard` — index

- **Description:** "Plan a motion piece (ad, reel, title, animated end card) before animating it: beat sheet on a tempo grid, storyboard panels, styleframes, an animatic to check timing at speed, and a build bible. Not for turning screen recordings into annotated storyboards."
- The last sentence of that description keeps it from triggering on the official recording-to-storyboard skill [C-180].
- **When:** any motion piece longer than about 2 s, or one with more than one beat. UI micro-motion skips it and goes to `motion`.
- **The stages** (§2.2, stages 3–8), each with the tool call and its exit gate.
- **Hard rules:**
  1. Frame 0 carries the message.
  2. Every line meets its read time [C-241].
  3. Every transition grows out of something already on screen.
  4. Retime at the animatic, never later.
  5. The build bible lists the frames to check.

#### `storyboard` — sections

**`beat-sheet`** (cites C-244, C-241, C-235):
- Choose a tempo where one beat is a whole number of frames [C-244].
- The table has these columns: bar.beat, t (s), frame, hit, on-screen copy, words, readable from–to, device.
- Major hits go on downbeats.
- One breath comes before the end card.
- The brand is fully visible by 3 s by default [C-235] [C-241], and the CTA holds for 2.5 s or more.
- Then map the table onto `figma_create_storyboard` panels: `durationS`, `beat`, `onScreen`, `action`, `camera`, `transition`, `audio`, `notes`.

**`boards`** (cites C-227):
- A panel is a decision, not an illustration.
- The panel conventions, and how to draw rough thumbnails into a `thumbId` with `figma_create_from_spec`.
- Every transition is motivated by something on screen.
- Read the tool's `offBeat` and `readTime` lists and fix them before going on.
- Exit gate: `figma_check_layout` returns ok on the board.

**`animatic`** (cites C-228, C-229, C-240):
- **Styleframes:** 3–6, through the `design` skill. Always include frame 0, the hero, the offer, the end card and one mid-transition frame.
- Snapshot them into the panels with `figma_import_image { renderNodeId, nodeId: thumbId }`.
- **Technical probe:** a sandbox frame for every mechanism nobody has measured.
- Then `figma_create_animatic`, a small render at the delivery fps (job mode), and `figma_review_video`.
- Retime by editing the caption text and re-running.

**`bible`** (cites C-240, C-193, C-206):
- Keyframes as data, one package per scene.
- The conventions: easing roles, cut pairs, resting state, masks, z-order.
- Where it lives: a file where the client has files, else text frames on the Storyboard page.
- The "frames to check" table: one line per frame, with what must be visible on it.

#### `motion` — index

- **Description:** "Animate on a Figma frame's timeline like a motion designer: pick the gear, block poses on the beat, shape curves so no frame pops, polish, then review at the delivery frame rate. Covers easing roles, transitions, kinetic type and Figma Motion's limits."
- **Gear:**
  - UI micro-motion: keys → `figma_check_motion` → one small GIF;
  - a piece: start with `storyboard`, then come back for the passes and `critique`.
- When a motion tool answers `UNSUPPORTED`, stop and deliver the static design [C-115].
- **Hard rules, each one a measured failure** [C-206]:
  1. Frame 0 carries the message, and the last frame is settled.
  2. Every key sits on the frame grid; cuts are cut pairs, never HOLD [C-240].
  3. No frame carries more than about a quarter of a big move unless its edge is blurred or covered. Check the keys with `figma_check_motion` before rendering [C-193].
  4. Offsets inside a group are 2 frames or more [C-242], and a hit peaks on its beat frame.
  5. Nothing holds dead for more than 0.5 s; holds drift.
  6. Check layout on every frame of drifts and holds, not only at rest.
  7. Every line meets its read time [C-241].
  8. Review at the delivery fps through several lenses, and re-check the neighbours of every fix.
- **Section list.**

#### `critique` — index

- **Description:** "Review a Figma design or motion piece like a panel of senior critics: run each lens in turn, measure every finding, write the fix as tool calls, merge fixes, re-check neighbours, and stop at the sign-off bar or after three rounds."
- **Set-up:** re-read the brief, and say what each lens judges.
- **Lenses by gear:**

  | Work | Lenses |
  |---|---|
  | a section | message, type and composition, finish QA |
  | a page or more | message, type and composition, colour and imagery, copy, originality, finish QA |
  | a motion piece | motion craft, design and type, technical QA, the brief's lens; originality once, at the styleframes |

- **Before each lens:** render, judge, and only then read your own build notes.
- **The finding schema, identical everywhere:**

  ```
  lens · score 1–10 · verdict pass | fix
  findings: severity (blocker | major | minor) · where (node name and id; for motion "t s (fN–fM)") · measured (the numbers) · problem (one sentence) · fix (tool calls or exact values)
  ```

- **The sign-off bar:**
  - no blocker or major finding;
  - every lens at 8 or above;
  - `figma_check_layout` ok (and `figma_check_motion` ok for motion);
  - every remaining tell justified;
  - the last round introduced no regression;
  - at most three rounds [C-239].

#### `critique` — sections

**`lenses`** (cites C-212, C-206, C-207, C-208): one checklist per lens. The squint test is `figma_export_node { maxSize: 200 }` [C-212]; the originality lens includes the default check.

**`motion-checks`** (cites C-193, C-245, C-240, C-241, C-242, C-243, C-196, C-206, C-222, C-230): the critic-derived checklist.
- A: from the keys (`figma_check_motion` covers most of it);
- B: every frame (`figma_review_video` metrics);
- C: cuts and handoffs;
- D: type and reading;
- E: layout over time;
- F: rhythm;
- G: finish and delivery.

**`sampling`** (cites C-194, C-195, C-197, C-205, C-246, C-247): how to see.
- **Still:** `figma_check_layout` craft and tells, `figma_export_node` at full size and at squint size.
- **Motion:** `figma_check_motion` first. Then one `figma_export_video` render per round, in job mode with your own `jobId`, at the delivery fps. Then `figma_review_video` for the contact sheet, close-ups around each transition from the bible's frames-to-check, frame-exact stills, and metrics.
- **Without ffmpeg** on the server machine: `figma_check_motion` numbers plus stills of the styleframes, and say that motion was not seen.

**`rounds`** (cites C-206, C-239):
- Merge conflicting fixes, choosing and saying why.
- Apply them in one batch.
- Run `figma_check_motion` and `figma_check_layout`.
- Render once.
- Re-check the neighbours of every change; the run had 4 regressions in round 2 [C-206].
- Report what is left after the last round.

### 1.3 The single source of truth

```

                             → catalog, resolveTopic, footer, promptBody, resources
```

The source rules:
- The frontmatter has only `name` and `description`, which are portable to every client [C-175].
- `name` equals the folder name [C-174].
- A body links a section in a form that works on every surface: ``section `easing` (references/easing.md, or figma_get_guide { topic: "motion", section: "easing" })``.
- There are no client-specific instructions.
- `src/` is not locked, and `scripts/check-language.mjs` already scans it.

## 2. The process the skills teach

The 2026-10-09 run is the model. That run had:
- 3 directors and 3 judges;
- a synthesis into a bible;
- a rig and 5 builders;
- 3 critics over 3 rounds, with a fixer after each.

**It cost about 60 agent passes and raised the critic scores from 6.5 to 8** [C-206]. It also missed two things:
- a styleframe stage, which would have caught the 14 findings visible at rest;
- an originality lens: the run's look matched a known generated cluster [C-208].

The single-agent version keeps every judgement as a pass with an exit gate and adds both missing stages.

| Run role | Single-agent pass |
|---|---|
| 3 directors | `directions`: write 2–3 direction cards one after another, each starting from a different source |
| 3 judges (craft, effectiveness, buildability) | Three scoring passes over the cards, each re-reading the brief first; then spine, grafts and restraint rules |
| Synthesis into a build bible | `bible` section, plus `figma_create_storyboard` and `figma_create_animatic` |
| Rig + 5 scene builders | One scene container per call, built from its styleframe; `figma_check_motion` after each scene |
| Builders' "ok" self-checks | Replaced by tool checks: `figma_check_layout` craft, `figma_check_motion` |
| 3 critics × 3 rounds, then the fixer | Lens passes on one render per round; merge; one batch of fixes; re-check the neighbours |

## 3. Tools: new and extended

The house rules apply to every tool here:
- portable schemas (`test/schema-portability.test.ts`): no `anyOf`, `oneOf`, `allOf`, `const`, `format` or `$ref`; a union travels as one string; exclusivity is checked in code and refused with `INVALID_PARAM` naming the field;
- nested objects are `.strict()`;
- descriptions are 1,024 characters or less;
- checks run before anything changes, and a refusal carries `partial: { created: [] }`.

### 3.1 `figma_check_motion` — NEW, read group

**Purpose.** The motion counterpart of `figma_check_layout`, with the same output contract. It evaluates every keyframe track per frame and judges the result against rules, each tied to a 2026-10-09 finding. It needs no render and no ffmpeg [C-193] [C-246].

**Parameters:**

| Param | Schema | Default |
|---|---|---|
| `nodeId` | string | the selection's top-level frame; several animated frames on the page and nothing selected → `INVALID_PARAM` listing them |
| `fps` | int 1–60 | 30 |
| `from`, `to` | number ≥ 0 (s) | the whole timeline |
| `bpm` | number 30–300 | none (turns on `beat_offset`) |
| `beatOffset` | number ≥ 0 (s) | 0 |
| `beatsPerBar` | int 1–12 | 4 |
| `rules` | `z.enum(RULE_IDS)` array, ≤ 30 | every rule |
| `minSeverity` | enum `error` \| `warning` \| `info` | `info` |
| `limit` | int 1–500 | 100 |
| `maxNodes` | int 1–5000 | 2000 |
| `thresholds` | strict object, every field an optional number: `stepShare` (0.4), `stepPx` (24), `strobeInfoPx` (60), `strobeWarnPx` (150), `strobeAnyBlurPx` (400), `aliveSpeedPx` (1), `deadSpanS` (0.5), `minHoldFrames` (3), `readSecondsPerWord` (0.3), `beatToleranceFrames` (1), `oneCurveShare` (0.7), `templateParents` (3), `templateShare` (0.4) | listed |
| `holds` | array ≤ 20 of strict `{ from: number, to: number }` (s) | none (intended holds, exempt from `dead_span`) |
| `brandId`, `ctaId` | string | none (turn on `brand_late` / `cta_short`) |
| `brandBy`, `ctaMinS` | number (s) | 3, 2.5 [C-241] |
| `includeActivity` | boolean | false |
| `session` | standard | |

**Rules.** Each rule cites the 2026-10-09 finding behind it; the evidence is in scratchpad `tools.md` §4.3.3.

| Id | Sev. | Rule |
|---|---|---|
| `vanish_mid_move` | warning | Visible extent drops from 0.4 or more to 0.02 or less in one frame, by the layer's own tracks, with blur under 6. From rest it is `cut_at_rest` (info) |
| `pop_in` | warning | Extent rises from 0.02 or less to 0.6 or more in one frame, by own size, scale or trim tracks; jump ≥ `stepPx` |
| `concentrated_step` | warning | One frame carries ≥ `stepShare` of a segment of 4 frames or more; the step is ≥ `stepPx` with blur under 6. A mask entry into a clipping parent is exempt |
| `strobe` | info / warning | Step ≥ `strobeInfoPx` with blur under 2 (info); step ≥ `strobeWarnPx` with blur under 2, or step ≥ `strobeAnyBlurPx` with any blur (warning) [C-243] |
| `blur_off_speed` | warning | On a segment whose fastest visible frame is 30 px or more: the blur on that frame is under 50 % of the blur peak within ± 6 visible frames, or the peak is 2 frames or more away from the speed peak |
| `one_frame_extreme` | warning | A scale, size or translation track reverses with its extreme held for exactly one frame (a cusp) |
| `arrival_not_held` | warning | An arrival with 25 % or more of its travel in its last frame, whose state lasts fewer than `minHoldFrames` frames |
| `dead_span` | warning | No visible layer moves faster than `aliveSpeedPx` per frame for `deadSpanS` or longer, outside `holds` |
| `cold_open` | warning | Frame 0 shows only the background, or nothing moves in the first 3 frames |
| `template_move` | info | One entry signature on layers under `templateParents` or more parents, or on `templateShare` or more of the animated layers. A clipping frame wrapping one layer is its mask; the mask's parent counts |
| `no_stagger` | info | Three or more siblings start the same move on the same frame; also `stagger_off_grid` [C-242] |
| `unrendered_extreme` | warning | An extremum key a quarter frame or more off the grid, or on a hidden frame; `off_grid` (info) for other keys; cut pairs exempt [C-240] |
| `easing_census` | info | One curve on `oneCurveShare` or more of the moves; LINEAR on an entry or exit of 4 frames or more and 24 px or more; stock back-ease or spring on 2 layers or more; named presets present |
| `hold_easing` | info | HOLD used: use a cut pair [C-240] |
| `beat_offset` | info / warning | With `bpm`: accents landing more than `beatToleranceFrames` from a beat or an eighth (info). A punch whose first change is on the beat frame, so its peak lands late (warning). Scene lengths |
| `read_time` | warning | A text fully readable for less than words × `readSecondsPerWord` (minimum 5/6 s); `dimmed_text` for text held at opacity 0.5 or less [C-241] |
| `rest_state_hidden` | info | Base opacity or scale is 0, so `figma_export_node` renders nothing |
| `timeline_end` | info | Keys after the end; reports `expectedFrames = ceil(d · fps) + 1`, d as Figma keeps it, to the microsecond [C-194] |
| `roundcap_zero_trim` | warning | A round-capped stroke at zero trim length while visible |
| `brand_late` / `cta_short` | warning | With `brandId` or `ctaId` |
| `first_key_late` | warning | A track whose first key comes after t = 0 with a value different from the base; add a key at 0 |
| `clamped_morph` | info | WIDTH and HEIGHT on different curves while CORNER_RADIUS ≥ min/2 (a stadium, not a circle) [C-196] |

**Fix text.**
- `vanish_mid_move` and `concentrated_step`: the engine tries the two replacement easings `cubic:0.45,0,0.55,1` and `cubic:0.65,0,0.35,1`, then names the one that brings the last visible extent down to 0.1 or less, with the recomputed number.
- `blur_off_speed`: blur keys whose peak lands on the fastest frame.
- Named Figma easings are evaluated approximately, and `limits` says so.

### 3.2 `figma_review_video` — NEW, export group, answered by the server alone

**Purpose.** Mine one render for a contact sheet, every-frame close-ups, frame-exact stills and per-frame metrics, with no Figma call and no second render [C-182]. It runs while the plugin is busy, and it works in any editor.

**Parameters:**

| Param | Schema | Default |
|---|---|---|
| `path` (required) | string inside the export roots | — |
| `every` | int ≥ 1 | ceil(frames / 90) |
| `columns` | int 1–16 | 9 portrait, 6 landscape |
| `tileWidth` | int 64–480 | 180 portrait, 240 landscape |
| `closeups` | array ≤ 6 of strict `{ startFrame: int ≥ 0, frames?: int 2–48 (24), columns?: int 1–12 (8) }` | none |
| `stills` | int[] ≤ 24 | none |
| `metrics` | boolean | true |
| `cuts` | int[] ≤ 64 | none (a jump on a declared frame is a `cut`, not a defect) |
| `holds` | array ≤ 20 of strict `{ fromFrame: int, toFrame: int }` | none |
| `expectFrames` | int ≥ 1 | none |
| `thresholds` | strict `{ freeze?, minFreezeS?, flicker?, flashLuma?, spike? }` | 0.15, 0.5, 1.0, 40, 20 [C-247] |
| `maxImages` | int 0–8 | 4 |
| `saveDir` | string | the video's folder |

There is no `session` parameter: no Figma file is involved.

**Behaviour:**
- One decode pass: `ffmpeg -i <path> -vf scale=270:-2:flags=area,format=gray -f rawvideo -pix_fmt gray -`, spawned with an argument array and no shell.
- Per frame it computes `diff` (mean absolute ΔY), `changed` (the share of pixels with |ΔY| > 8) and `luma` [C-247].
- From those it reports `freezes` (outside `holds`), `flickers`, `flashes` and `spikes` (both outside `cuts`), and the frame count from `ffprobe -count_frames`, against `expectFrames` [C-194].
- **Images:**
  - the sheet uses `select='not(mod(n\,E))'` and `tile`;
  - close-ups use `between(n\,k0\,k1)`;
  - stills are cut by index at `(k − 0.25)/fps` [C-195].
- Frame numbers are burned in with `drawtext` when this ffmpeg has it and a font is found; otherwise a note says so, and `sheet.tiles` maps every tile to its frame [C-205].
- No ffmpeg or ffprobe → `UNSUPPORTED`, with a hint that `figma_check_motion` works without it. A path outside the roots → `INVALID_PARAM`.

**Returns:** a JSON text block, then up to `maxImages` image blocks, each 5 MB or less inline (larger ones are written but not inlined). There is no `structuredContent`, because a client that prefers it would drop the images.

```jsonc
{ "path", "video": { "width", "height", "fps", "frames", "durationS" }, "frameCountNote"?,
  "sheet": { "path", "image": 1, "every", "columns", "tiles": [{ "index", "frame", "t" }], "labelled": true },
  "closeups": [{ "path", "image"?, "frames": [k0, k1] }], "stills": [{ "frame", "path", "image"? }],
  "metrics": { "analysisWidth": 270, "diff": [ … ], "summary": { "mean", "p95", "max", "maxFrame" },
               "freezes": [{ "from", "to", "s", "meanDiff" }], "flickers": [{ "frame", "diff", "skip" }],
               "flashes": [{ "frame", "lumaJump", "changed" }], "spikes": [{ "frame", "diff", "changed" }],
               "cuts": [{ "frame", "diff", "declared" }] },
  "findings": [{ "kind", "severity", "frames", "detail" }], "note"? }
```

**Split:** server only. New files `src/server/tools/review.ts` and `src/server/video-metrics.ts` (pure). `ops.ts`: export group, `BRIDGE_ONLY`.

**Editor cells:** yes / yes / yes (`everywhere()`).

## 4. The four defects

All four come from the 2026-10-09 record and are listed in `docs/superpowers/plans/2026-10-09-figjam-slides.md` § Defects. Diagnosis: `bug-move.md` and the bug-keyframes report.

**The common cause.** For stretches lasting from about a second to about 20 minutes, Figma listed the layers of an animated top-level frame under second ids. These are minted from a second root, and they stop resolving when the stretch ends. The ids returned at creation keep working throughout [C-199]. What starts such a stretch is unknown [C-200].

Our code turned that state into silent losses in three ways:
- it wrote x and y as two setters;
- it echoed keyframe tracks from the same synchronous run, without reading them back;
- it reported `getTopLevelFrame().id` and `timelines[0].id` as if they were the frame's own id.

**The fix principle** [C-250]: ok means "read back and found where it was asked to be".

### D1 — `figma_set_keyframes` kept only the last of several tracks; with `timelineDuration` it returned a foreign timeline id

- **Seen:**
  - fix round 1 at 07:46:48: three replacements, two kept their old keys, confirmed by a separate read 6 s later;
  - fix round 2 at 08:18:41: 7 of 7 multi-track steps lost every track but the last, 11 tracks in all;
  - every one-track step landed, and about 40 build-phase calls that only added fields landed [C-201].
- **Not the cause:**
  - `timelineDuration`: the duration already equalled 14.4, so `setTimelineDuration` never ran, and the round-2 failures had no duration at all;
  - concurrent writers;
  - build skew: the motion code is unchanged since `4e52cf1`.
- **Root cause:** not settled.
  - The best-supported hypothesis is H1a: in the second-id state, the replacements made in one synchronous run are computed from the record as it stood before the run, so the last one wins.
  - The alternatives are H1b (a handle fetched through an alias id applies from a stale snapshot) and H2 (the first write forks the timeline) [C-202].
  - On the code side: `setKeyframes.run` applies every track in one synchronous loop on one handle, and it builds the echo in the same run with no host turn [C-013].
- **Live probe to run:** `spikes/live-keyframe-tracks.mjs`, from `kfwork/live-keyframe-tracks.mjs`; the script is written and dry-run.
  - Cells `sameSync`, `sameYield`, `freshHandle`, `realHandle`, `keepIds`, `setter`, `adds` and `tool`;
  - phase A on a fresh frame;
  - then png, layer and video triggers, until one reproduces the loss;
  - then phase B;
  - a re-key detector;
  - an optional `MINIMIZE=1` mode.

  It settles C-202, C-185 (the `setter` cell) and C-204, and re-measures C-198.
- **Fix (safe under H1a, H1b, H2 and H3; ships before the probe):** in `src/plugin/ops/motion.ts`:
  1. Write the tracks as today, keeping the refusal handling.
  2. `await ctx.yieldToHost()`, once.
  3. Read every track back through a fresh `getNodeByIdAsync` handle.
  4. Re-apply only the missing tracks, one per host turn and each through a fresh handle, for at most 2 rounds; verify again.
  5. Read the timeline after the tracks settle, from the fresh handle. `setTimelineDuration` gets that id [C-183] [C-182].
  6. Report `topLevelFrameId`, with a `timelineNote` when it differs.
  7. If a track still has not landed, throw `INTERNAL` with `partial: { applied, notApplied }` and a hint to send those tracks one per call.

  The happy path costs one host turn: about 18–20 ms with Figma in front [C-050], and about 1 s with Figma in the background [C-124].

  `landed()` compares through the existing string forms: the key count, each t within 1e-4, the values, and the easing only where the agent gave one.

  If the probe shows that `keepIds` or `setter` accumulates in the losing state, step 1 switches to that form, and the verification stays as a guard. `remove_keyframes` gets the same verification.
- **Tests that fail on the old code** (`test/keyframe-verify.test.ts`; `run()` gets a hookable `yieldToHost`):
  1. **H1a, a coalescing fake** (applies are pending until a yield): all three replaced tracks end new; two report `rewritten`, one `written`.
  2. **H1b, a stale-handle fake:** the call converges, and each repair uses a new handle.
  3. **H3, a stale-read fake:** no re-applies; the echo comes after the yield.
  4. **H2, a timeline-fork fake:** `topLevelFrameId` and `timelineNote` are present, and `setTimelineDuration` gets the id read after verification.
  5. **A never-lands fake:** the error carries `partial { applied, notApplied }`, with at most 3 applies per field.
  6. **Cost:** on the normal fake, one apply per track and one yield.
  7. **Batch:** two `set_keyframes` steps under the coalescing fake are both verified.
- **Acceptance:** the probe's `tool` cell is all-new in both phases, and `spikes/live-wpF-motion.mjs` stays green.

### D2 — `figma_move_nodes` given x and y moved only y

- **Seen:** two circles at 08:19:49 (x stayed at -1176 and y moved to -241, absolute; and again with a relative move). Each answered `ok: true`. An x-only move landed, and so did an x and y move through the listed id [C-203].
- **Root cause (best-supported, H1):** `x` and `y` are both the translation column of one matrix, `relativeTransform` [C-186]. `modify.ts:449-450` writes them as two setters. Through a held id during a second-id period, each rewrite starts from the matrix as it was when the node was resolved, so the `y` write puts the old `x` back. `modify.ts:451` then answers ok without reading anything. H1 explains every move in the record (table in `bug-move.md`).
- **Fix:**
  - a `place()` helper in `src/plugin/write.ts` writes `relativeTransform` once when both coordinates are given, keeping the 2×2 part as read;
  - `offTarget()` re-reads the node with `getNodeByIdAsync` and compares within 0.01 px. A miss is `ok: false` with where Figma kept the layer; for an auto-layout child, the message says the layout places it;
  - `rotate_nodes` (rotation, then x, then y: three matrix rewrites) and `reparent_nodes` move to one final matrix write.

  The patch is ready (`scratchpad/skills/bugmove/fix.diff`, which `git apply --check` accepts). It was verified in a scratch copy: 1270 tests pass, and tsc passes for the server and the sandbox.
- **Live probe:** `spikes/live-move-twins.mjs`, from `bugmove/`. It waits for a second-id period, nudging with re-keys, creates and a GIF export, and asking the operator to press Play. Then it runs a matrix of raw rows and tool rows. It settles:
  - H1 versus H2;
  - whether a fresh lookup in the same op sees the new value. If not, `offTarget` reads the listed node (`parent.children` by name) instead;
  - C-200.

  The fix ships before the probe: it is correct under H1 and harmless otherwise.
- **Tests that fail on the old code:** `test/move-held-id.test.ts`, from `bugmove/move-held-id.test.ts`. 4 of its 7 tests fail on `a6ebb06`:
  - x+y through a held id;

### D3 — `figma_move_nodes` inside `figma_batch` answered `ok: true` without moving

- **Seen:** the S3 Kiln mask, as a batch step after a resize that landed (x stayed at 260, width 236) [C-203].
- **Root cause:** the same as D2. The batch path is not the cause:
  - the server parses each step with the tool's own shape (`batch.ts:127`);
  - the plugin runs the same op with the same params (`batch.ts:116`);
  - the fake gives identical results in a batch and standalone.

  The standalone call that "worked" used the listed id, so two things changed at once. Contributing: a step's `ok: true` means the step ran, and it can hide a failed item.
- **Fix:** D2's fix, plus `itemsFailed: [{ step, op, id, error }]` on the batch's success result (`src/plugin/ops/batch.ts`). The `figma_batch` description is updated.
- **Probe:** the `tool: batch move_nodes x+y (held)` row in `live-move-twins.mjs`.
- **Tests that fail on the old code:** the batch tests in `test/move-held-id.test.ts` above.

### D4 — "twin" ids (prefix `45:`) were readable, then every write said "not found"

- **Seen:** they resolved from 07:32 to 07:38. At 07:43 writes failed, and so did a read of the same id 8 s later. `getTopLevelFrame()` and `timelines[0].id` named second roots: `30:14989`, `42:15160`, `45:380`, `47:559`, `47:2168`. `figma_get_motion_context` passed them on as `topLevelFrameId` [C-199].
- **Root cause:** in Figma, second-id periods; their trigger is unknown [C-200]. In our code:
  - `get_motion_context` reports `getTopLevelFrame().id` as the frame's id and keys `timelineCohorts` by the timeline id, so one frame appeared under three ids;
  - the `NODE_NOT_FOUND` hint ("on another page, or deleted") misleads for this case;
  - nothing in our id handling creates or loses ids: `toNodeId` passes `45:442` through, and `getNodeByIdAsync` resolves it to null [C-187].
- **Fix:**
  - `topLevelFrameId` comes from walking `parent` to the page's child;
  - `timelineCohorts` are keyed by that frame and list every `timelineIds` seen, with a `note` when they differ;
  - a timeline id is labelled as a timeline id;
  - `set_keyframes` reports `timelineNote` (D1);
  - the `byId` and per-item "not found" hints add: "an id read from a listing inside an animated frame can be temporary; use the id your create call returned, or read the parent again";
  - the `safety` and `mechanics` guide sections carry the rule [C-199].
- **Probe:** none needed for the fix. `live-move-twins.mjs` (the lifetime phase) and `live-keyframe-tracks.mjs` (the re-key detector) measure the trigger and the lifetime.
- **Tests that fail on the old code:** `test/motion.test.ts` gains:
  - a fake in which `getTopLevelFrame()` returns a node whose id differs from the page child's: `topLevelFrameId` must be the page child's id, with one cohort listing both timeline ids;
  - a read of an unknown id whose hint must name temporary ids.

### Related defect found in the diagnosis — a client timeout threw away a running render

- **Seen:** the call was cancelled at about 60.4 s, twice. The cancel reached the plugin job, so the render was lost, although it would have taken 28–47 s. Every retry met the same timeout [C-197].
- **Root cause:** ours. `forwardTool` hands the client's `extra.signal` to `bridge.request`. On abort, `Bridge.cancel` settles the job as cancelled, and the bridge ignores the bytes when they arrive, although Figma cannot stop the render.
- **Fix:** job mode (§3.3) [C-249].
- **Test that fails on the old code:** in `test/export-video-jobs.test.ts`, an abort while waiting must not cancel the bridge job, and a retry must collect the render without a second request.
- **Probe:** none needed. The live acceptance is a 15 s 1080×1920 render through a 60 s client, which must return `rendering` and then be collected (`spikes/live-review.mjs`).
