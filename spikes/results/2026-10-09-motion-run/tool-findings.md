# figma-mcp defects seen while building the Moku ad v2 (2026-10-09)

- S3 builder: figma_move_nodes inside figma_batch returned ok:true but did not move S3/Kiln-mask (stayed x 260); a standalone figma_move_nodes moved it (x 243). Reproduce and fix; add a test.
- S3 builder: setting keyframes writes each node's t=0 OPACITY into its base opacity, so figma_export_node of a layer that starts invisible renders 1x1. Measured Figma behaviour; the motion guide should say so (render rest states BEFORE keyframing, or export_video frames).
OPEN, figma-mcp defects: (1) the 45:xxx twin ids are readable but every write to them fails with 'not found'; all writes used the 42:xxxx ids. (2) The first figma_set_keyframes call (with timelineDuration 14.4) returned a foreign timeline id (47:559) and silently dropped 2 of its 3 tracks (S1/Window WIDTH and TRANSLATION_X). A retry without timelineDuration applied them, and the full readback is clean. One later call (S4 · End card) also returned a foreign timeline id but did apply.
NOTE (figma-mcp defect): figma_set_keyframes with several tracks in one call (also inside figma_batch) applied only the last track. Its result echoed the old keys for the others, without an error. I re-sent every track as its own step and all landed (readback above).
NOTE (figma-mcp defect): figma_move_nodes given both x and y moved only y on the S3 circles (x stayed -1176). An x-only call worked.
NOTE (environment): this session's MCP client cancels figma_export_video after about 60 s, which also cancels the render. Rendered instead through the repo's spikes/mcp-client.mjs with a long timeout (r2-work/render.mjs); each render took 28-47 s. The MCP hub also restarted once mid-run (pid 25804 -> 24560).
NOTE (environment): Figma video export does not progress while the Figma window is minimized; the plugin stalled for about 40 min. I restored the window with SW_SHOWNOACTIVATE (no focus change), rendered, then minimized it again as it was. A later render needs Figma not minimized.
NOTE (spec E.1): `ffmpeg -ss (k+0.5)/30` as an input seek returns frame k+1, because frames before the seek time are dropped. The r2 check-<t>.png stills use (k-0.25)/30, so each is exactly frame k. Stills cut with the spec's formula are one frame late.
